# QPage — сайты из Google Формы

Как это работает:

```
клиент заполняет Google Форму
   → ответ попадает в Google Таблицу «QPage — анкеты»
   → скрипт таблицы делает для него лист (например «studio-lana»):
     тексты на ru / he / en (недостающие языки — машинный перевод), координаты адреса
   → и сразу собирает сайт: папка и ZIP в «QPage — сайты» на Google Диске
   → и публикует его на Netlify (если подключён): ссылка на сайт — на листе «Сайты»
   → вы проверяете лист, правите → меню «QPage → Сделать сайт из этого листа»
```

Генератор (эта папка) и анкеты остаются у вас. В папку сайта попадают только файлы сайта —
её можно отдавать клиенту и публиковать.

```

  QPage-generator\  генератор — эта папка, клиенту не отдаётся
    dist\QPortall-1-kod.gs      → файл Code.gs в Apps Script таблицы (собран build-gs.js)
    dist\QPortall-2-shablon.gs  → файл Shablon.gs там же (шаблон, часть 1)
    dist\QPortall-3-shablon2.gs → файл Shablon2.gs там же (шаблон, часть 2; большой файл редактор молча не сохраняет)
    dist\QPortall-4-anketa.gs   → файл Anketa.gs там же (своя анкета QPortall, см. ниже)
    dist\QPortall-5-yadro.gs    → файл Yadro.gs там же (ядро генератора; с ним Code.gs был 144 КБ и не сохранялся)
    dist\QPortall-6-stranica.gs → файл Stranica.gs там же (страница анкеты QPortall)
    anketa\               страница своей анкеты (её выкладывает «Опубликовать анкету QPortall»)

    tests\                проверки
  QPage-sites\      готовые сайты клиентов
```

## Установка (один раз, ~3 минуты)

Таблица «QPage — анкеты» уже создана у вас на Google Диске.

1. Открыть таблицу → «Расширения» → «Apps Script».
2. В открывшемся редакторе выделить всё в `Code.gs` (Ctrl+A) и вставить содержимое файла
   `dist\QPortall-1-kod.gs` (Ctrl+V). Добавить файл скрипта «+ → Скрипт» с именем `Shablon`,
   вставить в него `dist\QPortall-2-shablon.gs`. Так же файл `Shablon2` ← `dist\QPortall-3-shablon2.gs`, `Anketa` ← `dist\QPortall-4-anketa.gs`, `Yadro` ← `dist\QPortall-5-yadro.gs`, `Stranica` ← `dist\QPortall-6-stranica.gs`. Сохранить (Ctrl+S).
3. Вверху редактора в списке функций выбрать **setup** и нажать «Выполнить».
4. Google спросит разрешения (Формы, Таблицы, Диск, переводчик). «Продолжить» → выбрать свой
   аккаунт → если «Приложение не проверено»: «Дополнительно» → «Перейти в проект» → «Разрешить».
   Это ваш собственный скрипт, данные никуда кроме вашего Google не уходят.
5. Перейти на вкладку таблицы и нажать OK в окне со ссылками. Появится меню **QPage**;
   дальше оно появляется само при каждом открытии таблицы.

Новая версия скрипта: так же вставить `dist\QPortall-1-kod.gs`, `dist\QPortall-2-shablon.gs` и `dist\QPortall-3-shablon2.gs` вместо старого, сохранить и выполнить
**setup** — ничего заново не создаётся, только возвращается меню и показываются ссылки.
Если Google снова спросит разрешения (например «Подключение к внешнему сервису» для Netlify) —
разрешить, как в шаге 4.

## Каждый новый клиент

1. Отправить клиенту ссылку на форму («QPage → Ссылки»).
2. После ответа сайт собирается сам: в таблице появляются лист клиента (например «studio-lana»)
   и строка на листе «Сайты» со ссылками на папку сайта и ZIP в «QPage — сайты» на Диске.
3. Проверить машинный перевод (колонка «проверить перевод» в листе клиента), поправить,
   затем на этом листе: **QPage → Сделать сайт из этого листа**. Старая версия уходит в корзину.
4. Если Netlify подключён (см. ниже), сайт уже в интернете: ссылка в колонке «сайт в интернете»,
   после правки листа новая версия выходит по тому же адресу. Если нет — ZIP или папку
   перетащить в Netlify Drop.

Если обработка ответа не сработала: «QPage → Обработать последний ответ заново».

Если две анкеты пришли почти одновременно, сайты собираются по очереди: вторая сборка ждёт первую
(до 4 минут). Если ждать пришлось дольше, вторая не начинается, и Google присылает письмо об ошибке
скрипта — тогда на листе этого клиента «QPage → Сделать сайт из этого листа» (или «Обработать последний ответ заново»,
если листа ещё нет).

## Публикация в интернете (Netlify), один раз

1. Netlify → настройки команды (Team settings) → General → Visitor access →
   **Default project visibility → Public**. Иначе Netlify делает каждый новый сайт закрытым
   (открывается только после входа в ваш аккаунт Netlify).
2. Ключ доступа: https://app.netlify.com/user/applications#personal-access-tokens →
   «New access token», название «QPage», срок «No expiration» → «Generate token» → скопировать.
3. В таблице: **QPage → Подключить Netlify** → вставить ключ → «Сохранить». Скрипт проверит ключ.

Дальше каждый сайт публикуется сам: адрес `<имя листа>.netlify.app` (если имя занято — с коротким
хвостом). Колонки на листе «Сайты»: «сайт в интернете» и «Netlify: управление сайтом» (там можно
подключить свой домен). Если что-то не так, причина пишется в колонку «проверить»: сайт закрыт
для посетителей, форма заявки не распознана, Netlify не принял ключ и т. п. Сайт на Диске
собирается в любом случае.

Ключ хранится в свойствах скрипта таблицы, его видит только владелец. Отключить публикацию:
«QPage → Подключить Netlify» → пустое поле → «Сохранить». Ограничение Netlify: не больше
3 публикаций в минуту и 100 в день.

## Своя анкета QPortall (вместо Google Формы), один раз

Своя страница анкеты: по 2–4 вопроса на экране, фото без входа в Google, черновик сохраняется сам, в конце «Проверьте».
Ответы идут в ту же таблицу и собираются в сайт так же, как из Google Формы. Google Форма остаётся запасной.

1. Вставить в Apps Script все шесть файлов из `dist` (`QPortall-4-anketa.gs` — в новый файл `Anketa`, `QPortall-5-yadro.gs` — `Yadro`, `QPortall-6-stranica.gs` — `Stranica`: «+ → Скрипт»).
2. Apps Script → «Начать развертывание» → «Новое развертывание» → шестерёнка → «Веб-приложение»,
   «Запуск от имени: Я», «У кого есть доступ: Все» → «Начать развертывание» → разрешить → скопировать URL.
3. Таблица → F5 → **QPortall → Опубликовать анкету QPortall** → вставить URL → «Сохранить и опубликовать».
   Анкета появится на `https://qportall-anketa.netlify.app` (одна выкладка = 15 кредитов Netlify; если ничего не менялось,
   повторно не выкладывается). Ссылка — в «QPortall → Ссылки».

Что появится в таблице:
- **Анкеты QPortall** — каждая анкета: личный ключ, лист клиента, статус («ждёт сборки» → «готово»; «ошибка» →
  «QPortall → Анкеты QPortall: собрать ещё раз»). Колонки с ответами (JSON) не трогать.
- **Сайты** — новые колонки: «анкета: исправить» (личная ссылка клиента, можно переслать ему), «правок использовано»,
  «лимит правок» (по умолчанию 3; впишите своё число — и у клиента станет столько).
- **Настройки анкеты** — принимает ли анкета ответы (Да/Нет), сколько новых анкет в день, правок по умолчанию.
- **Фоны анкеты** — дизайн N = строка N, ссылка `…/?d=N`. Пять встроенных фонов («встроенный фон 1–5»);
  свой фон — ссылка на картинку в Google Диске. После изменения листа — «Опубликовать анкету QPortall».
  Нет такого номера или картинка не загрузилась — обычная анкета.

Исправление по личной ссылке: клиент видит свои ответы и фото, правит и нажимает «Сохранить исправления» →
тот же лист и тот же сайт. Строки листа, ответ на которые не менялся, остаются как есть (с вашими правками перевода);
ваши собственные строки (например `siteUrl`) тоже остаются. «Заказать сайт» внизу сайтов клиентов ведёт на анкету (без фона).

Защита: секретный ключ у каждого клиента, лимит правок, лимит новых анкет в день, выключатель, ловушка для роботов,
анкету быстрее 20 секунд не принимает.

Если менялся `QPortall-4-anketa.gs`: Apps Script → «Начать развертывание» → «Управление развертываниями» → карандаш →
«Версия: Новая версия» → «Начать развертывание» (адрес не меняется), затем «Опубликовать анкету QPortall».
Проверки на компьютере: `node tests/anketa-mock.js`, `node tests/anketa-e2e.js`, `node tests/anketa-audit.js <папка>`;
анкета локально: `node tests/anketa-server.js` → http://127.0.0.1:8090/.

## Логотип и фото

Вопросы с файлами скрипт создать не может (так устроен Google) — их добавляют в форму руками, один раз:
1. «QPage → Ссылки» → «Редактировать форму». В нужном месте «+» → тип вопроса **«Загрузка файлов»**.
2. Название начинается со слова **Логотип**: 1 файл, тип «Изображения», размер до 10 МБ.
3. Ещё один, название начинается с **Фото** (например «Фотографии для сайта»): до 10 файлов, «Изображения».
4. «QPage → Обновить форму» — добавит в форму новые вопросы из новой версии скрипта
   (например «Подписи к фотографиям») и проверит, что вопросы с файлами на месте.

Важно: чтобы приложить файлы, клиенту придётся войти в Google-аккаунт — так требует Google.
Файлы клиента копируются в папку «<лист> — фото» рядом с сайтом. Логотип там называется
`logo.png` (или .jpg/.svg/.webp), остальные картинки идут в галерею по алфавиту, до 8 штук.
Подписи — из вопроса «Подписи к фотографиям», по строке на фото: «Название — цена»
(цену можно не писать). С ценами галерея работает как меню или каталог.

Если клиент прислал фото в WhatsApp или по почте: положить их в папку «<лист> — фото»
(логотип назвать `logo.png`) и выбрать на листе клиента «QPage → Сделать сайт из этого листа».
Тяжёлые фото (больше 300 КБ) и фото HEIC с iPhone скрипт сам уменьшает: берёт у Google Диска
копию до 1600 точек по длинной стороне в JPG (логотип — до 800 точек; прозрачный PNG-логотип
остаётся как есть). Заодно фото встают правильно (не «боком») и теряют скрытые данные,
например место съёмки. Оригиналы остаются в папке «<лист> — фото», уменьшенные копии — в её
подпапке «для сайта (сжатые)»; если удалить подпапку, при следующей сборке копии сделаются заново.
Если Диск копию не дал, на сайт идёт оригинал, а HEIC пропускается — об этом пишется в колонке
«проверить». Файлы больше 1,5 МБ, которые остались большими, он тоже отметит там.

## Генератор на компьютере (необязательно)

Тот же генератор можно запускать на компьютере (нужен Node.js 18+):
1. В Apps Script: «Начать развертывание» → «Новое развертывание» → «Веб-приложение»,
   «Выполнять как: Я», «Доступ: Все» → скопировать URL.
2. В `config.json`: `url` — этот адрес, `token` — ключ из «QPage → Ссылки».
3. `generate.cmd --list`, затем `generate.cmd <имя листа>` → сайт в `C:\ClaudeWork\QPage-sites\`.
   Без веб-приложения: лист → «Файл → Скачать → CSV» → `generate.cmd --csv файл.csv --name имя`.
   Логотип и фото: скачать папку «<лист> — фото» и добавить `--media путь\к\папке`.

После изменения шаблона или ядра пересобрать файл для Google: `node build-gs.js` и вставить
`dist\QPortall-1-kod.gs`, `dist\QPortall-2-shablon.gs` и `dist\QPortall-3-shablon2.gs` в Apps Script заново.

## Поисковики (Google) и превью ссылок

Каждый сайт собирается уже «готовым для Google»: весь текст основного языка записан прямо в `index.html`
(поисковики и проверки HTML видят его без скрипта), заголовок H1 = вид деятельности + название,
описание 120–155 знаков, теги Open Graph (превью ссылки в WhatsApp/Facebook — первое фото или логотип),
карточка бизнеса для Google (JSON-LD LocalBusiness: телефон, адрес, координаты, часы работы), `robots.txt`.
Если известен адрес сайта, добавляются ещё `sitemap.xml`, `canonical` и `og:url`: при публикации
на Netlify адрес берётся сам; свой домен — строка `siteUrl` в листе клиента (поле `siteUrl`, значение
`https://…`), на компьютере — `--url https://…`.
Чтобы Google быстрее нашёл новый сайт: Google Search Console → добавить сайт → «Файлы Sitemap» → `sitemap.xml`.

## Что заполняется автоматически, а что нет

- Языки сайта — те, что выбрал клиент; переключатель показывает только их.
- Название на другие языки машинно **не** переводится: берётся из полей «Название на иврите /
  латиницей», иначе остаётся исходное (генератор об этом напомнит).
- Логотип и фото — из вопросов «Загрузка файлов» (см. ниже). Нет логотипа — круг цвета сайта
  с первыми буквами названия. Нет фото — блок «Фотографии» скрыт.

- Карта — если клиент дал адрес и выбрал «Карта». Координаты ищет Google; если не нашёл,
  кнопки Google Maps/Waze ищут по адресу, а встроенной карты нет.
- Форма заявки — режим Netlify Forms: заработает после публикации на Netlify (при автопубликации
  скрипт сам включает распознавание форм и проверяет, что форма найдена). Заявки видны в Netlify
  → сайт → Forms. До публикации при отправке сайт честно пишет «Не удалось отправить заявку».

## Необязательные блоки анкеты (цепочка «Да / Нет»)

После «Частых вопросов» анкета спрашивает по очереди: прайс-лист, отзывы, «Как мы работаем»,
лицензии и дипломы, видео YouTube. «Да» открывает страницу с вопросами этого блока, «Нет» — сразу
следующий вопрос, лишнего клиент не видит. Если клиент сначала ответил «Да», а потом передумал,
ответы этого блока не берутся. На сайте блок появляется, только если в нём что-то заполнено.

- Прайс-лист: по строке «Название — цена»; строка с двоеточием в конце — заголовок группы.
  Можно дать ссылку на файл с ценами (https://…) — на сайте будет кнопка.
- Отзывы: одно поле, до 4 отзывов, каждый с новой строки, имя в конце через тире: «Всё отлично — Анна К.».
- Лицензии: текстом, по строке; ссылка на скан — кнопкой.
- Видео: ссылка YouTube встраивается и загружается только после нажатия (youtube-nocookie);
  ссылка на Instagram, TikTok и т. п. — кнопка «Смотреть видео», открывает видео там.

Часы работы: галочки «Рабочие дни» и выпадающие списки «Начало работы», «Конец работы»,
«В пятницу работаем до» (или «Как в другие дни»). Сайт сам пишет «Вс–Чт 8:00–19:00, Пт 8:00–13:00» на каждом языке, без перевода. На листе
клиента: `workDays` (вс, пн…), `workHours`, `fridayHours`; старое текстовое поле `hours` тоже работает.

Внизу каждого сайта: логотип QPage и «Сайт сделан на QPage · Заказать сайт» со ссылкой на анкету.
Другой адрес (например, страница о QPage): свойство скрипта `ORDER_URL` (Настройки проекта → Свойства скрипта).

Ещё новые вопросы: «Районы и города, где вы работаете» (в «Контактах»), «Главная кнопка сайта»
(Оставить заявку / Заказать / Записаться — меняет текст кнопок и заголовок формы) и «Заявление
о доступности» (Да/Нет; дата заявления — день сборки сайта). На листе клиента для них строки
`areas`, `pricelist`, `reviews`, `steps`, `license` (по языкам) и `cta`, `a11y`, `priceLink`,
`licenseLink`, `video` (одно значение) — их можно править и пересобрать сайт.
Если ссылка неверная, сайт собирается без неё, а причина пишется в колонке «проверить».

Уже созданная форма: вставить новый `dist\QPortall-1-kod.gs`, `dist\QPortall-2-shablon.gs` и `dist\QPortall-3-shablon2.gs`, затем «QPage → Обновить форму» — вопросы
и цепочка добавятся на свои места, устаревшие (8 полей отзывов) уберутся, «Подписи к фотографиям»
встанут сразу после вопроса с фото. Ссылка на форму и вопросы с файлами не меняются.

## Проверка сайта в браузере (по желанию)

Генератор сам проверяет файлы и тексты. Полная проверка (3 размера экрана, все языки, доступность,
форма, карта, QR) — один раз установить: `npm install` и `npx playwright install chromium`,
затем `npm run check -- ..\QPage-sites\<имя>`.
